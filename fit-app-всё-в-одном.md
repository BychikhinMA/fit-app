# Часть I. Что это за проект

**fit-app** — мобильное приложение для тренировок и питания. Expo / React Native, TypeScript. Лежит в `~/Desktop/fit-app`, разрабатывается через Claude Code, код на GitHub.

**Что уже работает:**

- Онбординг из 8 шагов: цели, мотивация, параметры тела
- Расчёт ИМТ и нормы калорий по формуле Mifflin-St Jeor — считается по-настоящему
- Библиотека из 741 упражнения из free-exercise-db с русским переводом и размеченными группами мышц и оборудованием
- Адаптивная навигация: сайдбар на широком экране, таб-бар на узком
- Пять разделов: Главная, Тренировки, Питание, Библиотека, Профиль
- Бело-оранжевая тема
- Supabase подключён, миграции 0001–0003 применены

**Что пока заглушка:**

- Генерация плана тренировок и питания — `plan-stub.ts`, ключ Claude API не подключён
- Вход — две захардкоженные карточки «Максим» и «Мария», без пароля
- RLS в Supabase открыт для `anon` — данные доступны анонимно

**Главный документ проекта:** `roadmap-auth-ai-design.md` в корне репозитория. Claude Code читает его перед каждым шагом. Всё, чего нет в этом файле, построено не будет.

# Часть II. Мои требования

## 1. Пользователи и доступ

**Личные аккаунты через авторизацию.** Подключаться должны не только я и Мария, но и отец, друзья, в перспективе — шире. Офлайн-режим не требуется.

**Сторонняя авторизация** — вход через Google и Apple.

**Совместный доступ по приглашению.** Мария видит мой календарь, упражнения и прогресс — только если я дал доступ. Не общий план на двоих, не автоматическая видимость. Приоритет — «на потом».

> **Внимание, важное.** Текущий Шаг 4 роадмапа спроектирован как «семейный MVP»: подтверждение email отключено, RLS открыт для `anon`. Под расширенный круг пользователей это дыра — данные всех будут доступны всем. Шаг 4 нужно пересмотреть до начала работы над ним.

> **Про Apple.** Если добавляю вход через Google, Apple требует также добавить Sign in with Apple. Иначе приложение не пройдёт модерацию в App Store.

## 2. ИИ и планы тренировок

- **Генерация плана** через ИИ — это Шаг 3 роадмапа, Edge Function вместо `plan-stub.ts`
- **Ручная корректировка** сгенерированного плана
- **Оценка от ИИ:** после правок спросить, насколько план корректен и поможет
- **Выбор подхода к плану** — не упражнений, а методологии: комплекс на все группы мышц либо сплит по отдельным частям
- **Выбор зон тела**, на которые хочу сделать упор
- **Рекомендации ИИ** под конкретные возможности и обстоятельства

## 3. Библиотека упражнений

**Выбор аналогов.** ИИ дал план, сегодня прорабатываю такую-то группу мышц — я открываю список замен и вижу подсветку, насколько замена эффективна.

База из 741 упражнения с размеченными группами мышц и оборудованием уже есть — подбор «на ту же группу» технически возможен без ИИ. ИИ нужен только для оценки равноценности.

*Оговорка: это самая непростая функция из списка. «Насколько эффективно» требует модели сравнения упражнений. Стоит обсудить отдельно перед реализацией.*

## 4. Календарь

- Недельная сетка вместо линейного списка «День 1 · Ноги · Дом»
- Перенос тренировок между днями
- Назначение времени тренировки
- Совместный просмотр — зависит от авторизации

## 5. Прогресс

Геймифицированные шкалы, как в игре, по основным характеристикам: **вес, масса, объём мышц, количество подходов, рабочие веса.**

Таблица `progress_metrics` в базе уже есть — фундамент частично заложен.

## 6. Дизайн

**Ориентир — Apple.** Human Interface Guidelines: сдержанность, воздух, системная типографика, минимум декора.

**Убрать «след ИИ».** Приложение сейчас узнаётся как сделанное нейросетью. Конкретные признаки, которые видно: на главном экране четыре подряд идущие одинаковые серые карточки, под каждой цифрой — пояснительный абзац мелким шрифтом.

*Стоит делать отдельным шагом, а не примешивать к функциональным задачам.*

## 7. Баг

**В библиотеке упражнений** можно подсветить несколько чипов группы мышц одновременно, хотя фильтр применяется только один. Визуальное состояние врёт про фактическое.

*Дешёвый и заметный баг, чинить в первую очередь.*

# Часть III. Открытые вопросы

Ответы нужны, чтобы список требований стал полным.

1. **Шкала прогресса — относительно чего максимум?** Относительно цели из онбординга, относительно нормы для моих параметров, или относительно моего же результата месяц назад? Без ответа шкалу нарисовать нельзя.

2. **Нужен ли дневник питания?** В приложении есть вкладка «Питание» и таблицы `meal_plans`, `food_log_entries`, `nutrition_logs`. Я про эту часть не говорил ничего.

3. **Какие «обстоятельства» учитывает ИИ при рекомендациях?** Оборудование, время на тренировку, травмы и ограничения, место (дом/зал), частота в неделю?

4. **Что не так с расположением библиотеки во вкладках?**

5. **Что происходит после достижения цели?** План перегенерируется, ставится новая цель?

# Часть V. Телефон и Мария

**На свой телефон — можно сегодня.** Ставлю Expo Go из App Store, в терминале `npx expo start`, сканирую QR камерой. Телефон и Mac должны быть в одной Wi-Fi.

**Марии — сложнее.** Даже когда она откроет приложение, это будет отдельная копия с отдельными данными: сейчас всё хранится локально на устройстве. «Мы вдвоём в одном приложении» не выйдет, пока данные не переехали в Supabase и не появилась авторизация.

**Полноценная установка** — TestFlight у Apple, внутреннее тестирование у Google. Требует аккаунта разработчика Apple, 99 $/год, и сборки через EAS. Отдельная задача, не входит ни в один шаг роадмапа.

# Часть VI. Что сделано в этой сессии

**Плагины Claude Code.** Разобрали гайд из Telegram про 5 плагинов. Установлен `claude-code-setup` (официальный, от Anthropic) и переустановлен `expo`. Два плагина из гайда отклонены: **OmniRoute** — потому что он не даёт бесплатный Claude, а подменяет его сторонними моделями и пропускает весь код через чужой шлюз; **Claude Mem** — потому что официальный плагин `remember` уже стоит и делает то же самое, две системы памяти дрались бы за один контекст.

**Шаг 2 роадмапа — бело-оранжевая тема.** Коммит `5e9e25e`, влит в `main`.

Что изменилось: заведены токены `accent` (#FF7A1A / #FF8A3D), `onAccent` (#1A1A1A / #000000), `accentText` (#C2410C / #FDBA74). Правки в `chip.tsx`, `onboarding/index.tsx`, `tab-trigger-button.tsx`, `themed-text.tsx`, `exercise-library/[id].tsx`.

**Решения по контрасту, которые стоит помнить:**

- Белый текст на `#FF7A1A` даёт 2.6:1 — не проходит даже порог 3:1 для крупного текста. Поэтому `onAccent` тёмный, а не белый: `#1A1A1A` на той же оранжевой даёт 6.7:1
- Оранжевый **не используется как цвет текста** на светлом фоне. В навигации оранжевая только иконка, подпись остаётся `theme.text`
- Для акцентного текста заведён отдельный токен `accentText` = `#C2410C`, это 5.2:1 на белом
- Попутно исправлен баг: неактивная кнопка онбординга рисовала белую подпись на светлом фоне, 1.05:1 — текст был невидим

**Документация.** Коммит `fbe3ba7` — `CLAUDE.md` и `roadmap-auth-ai-design.md` приведены в соответствие с кодом, все отклонения от плана зафиксированы с причинами.

**Уборка.** Ветки `step1-adaptive-navigation` и `step2-color-theme` удалены локально и на origin. В репозитории осталась одна `main`.

# Часть VII. Как работать с Claude Code дальше

Что оправдало себя в этой сессии:

**Ручной режим вместо auto.** `Shift+Tab` переключает. В auto-режиме Claude Code правит файлы не спрашивая — для смены цветовой темы на десятки файлов это рискованно.

**Сначала план, потом код.** Формулировка «покажи план: какие файлы затронешь и что именно поменяешь, пока ничего не правь» экономит время. Без неё он начинает править по одному файлу, и решения принимаешь вслепую.

**Каждый шаг — своя ветка.** Смешивать перекраску и починку логики в одной ветке нельзя: если что-то пойдёт не так, откатывать придётся оба.

**Правило про область работ.** Записано в память Claude Code: не трогать файлы вне согласованного плана без одобрения и показывать полный вывод верификации. Он один раз молча взял файл вне плана — правка была верная, но узнал я об этом случайно.

**Проверять глазами.** Расчётный контраст 1.22:1 для подложки активного пункта навигации выглядел провальным на бумаге, а живьём оказался нормальным — работают ещё оранжевая иконка и жирное начертание.
